# atreyakamat.dev — DESIGN.md
## Creative Direction v2

## 1. Design Thesis

atreyakamat.dev should feel like the digital identity of a small,
high-end independent studio — except the studio is one person.

The visual intersection is:

EDITORIAL DESIGN
× PERSONAL PORTFOLIO
× CREATIVE STUDIO
× PRODUCT DESIGN
× SOFTWARE CRAFT

The website must remain professionally credible for recruiters and
technical clients while having enough art direction to be memorable.

The objective is NOT to make a "developer-looking website."

The objective is to make an exceptionally designed personal website
for someone who happens to build software.

---

## 2. Core Visual Language

The visual system consists of five ingredients:

01. LARGE EDITORIAL TYPOGRAPHY
02. HUMAN PHOTOGRAPHY
03. GENEROUS NEGATIVE SPACE
04. TURQUOISE BRAND SIGNALS
05. SMALL, DELIBERATE INTERACTIONS

Pages should alternate between expressive moments and quiet moments.

Do not make every viewport visually loud.

---

# 3. Typography Direction

## Display Typography

Use a HIGH-CONTRAST EDITORIAL SERIF inspired by the supplied
"Astonishingly, Awesome." reference.

Characteristics:

- dramatic thick/thin stroke contrast
- elegant proportions
- sharp or refined serifs
- oversized display capability
- beautiful lowercase forms
- strong editorial personality
- slightly fashion/editorial feeling
- not vintage
- not decorative script

The serif should create the site's memorable moments.

Potential font directions to evaluate:

- Instrument Serif
- DM Serif Display
- Bodoni Moda
- Cormorant Garamond
- Playfair Display
- Libre Caslon Display

Do NOT select a font merely because it is serif.
Test large hero compositions before final selection.

Premium/commercial fonts may be considered later if licensing permits.

---

## Sans-Serif Typography

Pair the display serif with a neutral, extremely clean grotesk.

Potential direction:

- Geist
- Inter
- Manrope
- Suisse-style grotesk
- Neue Montreal-style grotesk

The sans-serif handles:

navigation
body copy
project metadata
buttons
experience
skills
technical information
captions

---

## Typography Hierarchy

DISPLAY SERIF:
Emotion / identity / statements.

SANS:
Information / interface / navigation.

This contrast is fundamental to the identity.

Example:

small sans:
SELECTED WORK / 2026

large serif:
Things I've built.

small sans:
Products, systems and experiments.

---

# 4. Hero Typography

Do NOT use a conventional:

"Hi, I'm Atreya Kamat — Full Stack Developer"

layout.

Create an editorial composition.

Example structural direction:

        small sans
        HELLO, I'M ATREYA

        enormous serif
        I make useful
        things happen.

        sans supporting text
        Software engineer and product builder
        based in Goa.

Portrait integrated into composition.

The headline may partially interact with/cross behind the portrait
when readability remains excellent.

The portrait and typography should feel art-directed together.

# 10. Full-Colour Editorial Moments

Occasionally allow an entire viewport/project transition to become:

TURQUOISE background + INK typography

or

VERMILION background + CREAM serif typography

These moments should be rare.

Think editorial chapter divider, not permanent website theme.

The supplied orange typography reference demonstrates the desired
contrast philosophy:

strong flat colour
+
enormous elegant serif
+
almost no visual clutter.

---

# 11. Photography

Photography is treated as editorial material.

Use:

large crops
full-bleed photographs
unexpected aspect ratios
portrait cutouts
occasional monochrome treatment
soft turquoise atmosphere
candid professional imagery

Do not place every photograph inside rounded cards.

Some photography should touch viewport edges.

---

# 12. Project Presentation

Projects should resemble editorial features rather than SaaS cards.

A flagship project can occupy nearly an entire viewport.

Example:

A monitoring system designed to
notice problems before users do.

2026                         VIEW PROJECT ↗

The visual does most of the communication.

# 13. Components & Interaction Libraries

Fancy Components and Magic UI are APPROVED component sources.

They are not visual direction sources.

Every imported component must be:

recoloured
rescaled
re-timed
re-typographed
simplified

until it belongs naturally to atreyakamat.dev.

Never leave library-default aesthetics.

Potential component categories:

Fancy Components:
- typography interactions
- media transitions
- stacking project presentation
- subtle parallax
- marquees
- hover transformations

Magic UI:
- Blur Fade
- Hero Video Dialog
- Lens
- Progressive Blur
- subtle animated backgrounds

Additional component references supplied later should be documented
in a dedicated:

DESIGN REFERENCES

section with:

URL
component name
intended location
reason for use
mobile behaviour
performance consideration

Do not implement reference components until their purpose is defined.

---

# 14. Buttons & Links

Avoid oversized SaaS pill buttons.

Prefer editorial links:

View project ↗
GitHub ↗
Resume ↗
Let's talk ↗

Primary CTAs may use filled turquoise.

Secondary interactions should usually remain text-based.

Arrow movement of 3–5px on hover is sufficient.

---

# 15. Borders & Radius

The site should NOT become excessively rounded.

Images:
0–16px depending on composition.

Containers:
8–16px.

Buttons:
moderate radius.

Some editorial elements may have ZERO radius.

Use geometry intentionally.

---

# 16. Texture

Allow an extremely subtle paper/noise texture.

It should only be noticeable when deliberately looking for it.

No obvious grain overlay.

The texture exists to prevent the white surfaces from feeling
sterile.

---

# 17. Motion Personality

Motion should feel like a premium design studio:

precise
smooth
restrained
slightly playful

NOT:

bouncy
game-like
futuristic
constantly animated

Use motion to reveal hierarchy.

# 21. Final Design Rule

When choosing between:

MORE EFFECTS

and

BETTER TYPOGRAPHY

choose typography.

When choosing between:

MORE COMPONENTS

and

BETTER PHOTOGRAPHY

choose photography.

When choosing between:

MORE INFORMATION

and

BETTER HIERARCHY

choose hierarchy.

The site's sophistication should come from taste, not complexity.

## Component Density Rule

The approved Fancy Components, Magic UI and ReactBits components form
the interaction library for atreyakamat.dev.

They are NOT a checklist of effects that must appear simultaneously.

Every major viewport may contain:

- ONE primary expressive interaction
- ONE optional supporting microinteraction
- otherwise normal typography, photography and whitespace

Never place two competing animated text treatments in the same viewport.

Never use:
Morphing Text + Comic Text + ASCII Text + Curved Loop
together merely because they are available.

All third-party components must inherit the atreyakamat.dev visual system:

Porcelain  #F7F5EF
Ink        #151515
Aqua       #32D6C5
Vermilion  #F05A3C

and the approved editorial serif + grotesk typography system.

Effects must feel authored for this website rather than imported from
a component library.

DESKTOP ENHANCEMENTS:
Smooth Cursor
Gravity
full Parallax Floating
advanced SVG-path animation

MOBILE FALLBACK:
native cursor
static/low-motion physics
reduced parallax
touch-first interactions
poster-first video loading

prefers-reduced-motion:
disable all non-essential continuous animation.

Performance rule:
No animation library or component may be loaded globally when it is
only required by one route.

Route-level and component-level lazy loading are required for heavier
interactive components.
